# Progress report — dental occlusal screening assistant

2026-09-24. Research prototype; a screening aid, not a diagnosis. Companion:
`docs/architecture.md` (system design).

## 1. Goal

From two occlusal photos and a short interview, tell a patient which teeth
may have decay, how soon to see a dentist, and why. It runs fully locally
on one PC (RTX 3060, qwen3:14b).

## 2. What changed since the last meeting

**Triage moved from fixed rules to "LLM proposes, code guards".**
- The LLM proposes an urgency level and must cite criteria from a
  literature-based protocol (SDCEP 2nd ed. 2026, NHS England 2025), with the
  patient's own words as evidence.
- Code evidence-checks every citation.
- A red-flag floor (swelling, fever, breathing or swallowing difficulty,
  trauma, uncontrolled bleeding, and others) forces EMERGENCY before any
  model call.
- The protocol's own criteria can only **raise** the model's level, never
  lower it.

**The interview became checklist plus short chat.**
- Red flags and yes/no items are explicit clicks with no default.
- Only 5 descriptive fields (pain relief effect, severity, triggers,
  location, duration) are extracted by the LLM, and each needs a verified
  quote.

**Safety guardrails on the explanation text:**
- no drug names or doses;
- no invented teeth;
- no invented pain side;
- a missing tooth is never called decay;
- follow-up answers don't repeat the first response.

**Protocol v0.2** (approved wording, going live next) adds two checklist
questions, broken filling and pus. Before this, those could only be picked
up if the patient happened to mention them.

## 3. Results

| Measure | Result | n | Note |
|---|---|---|---|
| Explanation faithfulness: invented teeth / omissions / contradictions | 0 / 0 / 0 | 60 synthetic + 8 seed | qwen3:14b; the 4B model is not deployable (invented teeth in 40%) |
| Symptom extraction, blind held-out dialogues | **92.6%** of fields (88/95, 95% CI 85.4–97.0) | 19 dialogues | 0 guessed values; misses come back as empty, not wrong |
| Symptom extraction, development dialogues | 100% (60/60) | 12 | tuned on these, so optimistic |
| Triage, rules-only baseline vs SDCEP-derived keys | under-triage 25.5% (51/200) | 200 held-out vignettes | the old design |
| Triage, protocol criteria in code | under-triage 4.0% (8/200), weighted κ 0.967 | 200 | no LLM yet; code agreeing with a key built from the same protocol |
| Tooth segmentation | median 12 teeth per photo | Mendeley set | reliable |
| Caries detection | catches 29% of carious photos at conf 0.50 (62% at 0.25) | 4,929 photos | weakest link; threshold is a clinical decision |

**Caveat that travels with every triage number:** these figures measure
agreement with SDCEP *as encoded in our draft protocol*. They are not
clinical validation. No dentist has reviewed the protocol yet.

## 4. Method safeguards

- **Pre-registered evaluation.** The Test 5 analysis (primary endpoint:
  under-triage with exact CIs; weighted κ; McNemar LLM vs rules) was written
  before any held-out scoring. Every amendment is dated before scoring.
- **Blind test material.** The developers never see held-out keys or
  dialogues. One accidental exposure (one case) was logged, and a sensitivity
  analysis excluding the 6 affected cases was declared before scoring.
- **Realistic test text (P7).** One model family (Llama) writes patient-style
  text, a second (Gemini, paid API, synthetic text only) checks it blind,
  and a third (Qwen) is the system under test. A set is used only if the
  blind check disagrees on ≤ 2% of fields.
- **A negative result is reported.** Silver urgency labels mined from an
  online doctor Q&A corpus failed their pre-registered bars (κ 0.27–0.41 vs
  0.60), so they were dropped.

## 6. What we need

- **A dentist** for about 2–3 hours. Their review decides whether the
  protocol and knowledge base can lose their draft status. The review packet
  is ready (`docs/dentist-review/`: protocol review, blind vignette
  labelling, 11 open clinical questions, knowledge review). Key open calls:
  - the caries threshold;
  - whether to ask about trismus, visual disturbance or voice change;
  - pus without pain;
  - cavity plus any pain → URGENT.
- **Licences.** The SegmentAnyTooth weights (non-commercial) and the caries
  weights (GPL-3.0) are fine for research but not cleared for a product.
